# 贴图收集健壮性改进方案

## 问题描述

导出复杂场景时，贴图收集存在以下问题：

1. **贴图收集不稳定**：部分贴图能收、部分不能，原因不明
2. **Redshift Dome Light HDR 贴图收集失败**：场景中有 Redshift Dome 灯光时，灯光上连接的 HDR 贴图无法收集
3. **动态贴图（帧序列）无法收集**：带 `####` / `%04d` 帧号模式的贴图路径因 `os.path.isfile()` 检查失败被跳过
4. **置换贴图收集不完整**：displacement 连接存在但 `listHistory` 追溯不到
5. **贴图上游调色节点网络复杂时漏收**：如 colorCorrect、remapColor 等节点后的贴图链路可能遗漏

---

## 根因分析

### 根因 1：`listHistory()` 只能覆盖部分上游连接

**位置**：[`zjg_exporter.py:208`](file:///e:/TRAE_Project/MaterialManagementPro/squirrel_asset_manager/integration/zjg_exporter.py#L203-L238)

当前 `_collect_texture_paths_from_materials()` 依赖 `cmds.listHistory(mat, allConnections=True)` 来遍历材质上游所有节点。虽然 `allConnections=True` 会包含不只是构造历史的节点，但 `listHistory` 仍有局限性：

- 某些渲染器特定连接不会被 Maya 视为「历史」连接
- 节点图跨越 shadingEngine 到 material 的边界时可能不完整（如 displacement 通过 `shadingEngine.displacementShader` 连接）
- 多层嵌套的节点网络（材质 → 调色 → 混合 → 调色 → 贴图）中部分分支可能被截断

### 根因 2：只识别 `file` 节点类型，遗漏其他贴图载体

**位置**：[`zjg_exporter.py:210`](file:///e:/TRAE_Project/MaterialManagementPro/squirrel_asset_manager/integration/zjg_exporter.py#L210)

```python
if cmds.nodeType(node) == 'file':
```

当前代码只检查 `nodeType == 'file'`，但 Maya 中有多种节点可以承载贴图路径：

| 节点类型 | 贴图属性 | 渲染器 |
|---------|---------|--------|
| `file` | `.fileTextureName` | 通用 |
| `aiImage` | `.filename` | Arnold |
| `RedshiftNormalMap` | `.tex0` | Redshift |
| `RedshiftBumpMap` | `.tex0`, `.tex1` | Redshift |
| `RedshiftSprite` | `.tex0` | Redshift |
| `RedshiftVolumeShape` | `.fn` | Redshift Volume |
| `place2dTexture` | 通过 `file` 间接关联 | 通用 UV |

### 根因 3：灯光贴图（Dome Light HDR / IES）未被收集

**位置**：[`export_orchestrator.py:1049`](file:///e:/TRAE_Project/MaterialManagementPro/squirrel_asset_manager/core/export_orchestrator.py#L1049-L1097)

`_stage_textures()` 的收集流程：

1. 从 `associated_objects` 收集材质 → 收集贴图
2. **完全不处理灯光节点**

对于 RedshiftDomeLight、aiSkyDomeLight、VRayDomeLight 等环境光：
- `RedshiftDomeLight.tex0` → HDR 贴图
- `aiSkyDomeLight.ai_filename` 或连接的 `file` 节点
- `VRayDomeLight.domeTex` 的连接 → `file` 节点

**注意**：`light_io.py` 中已经有完善的 `get_connected_texture_files()` 函数处理灯光贴图收集，但在场景导出流程 `_stage_textures()` 中**未被调用**。

### 根因 4：帧序列贴图模式匹配失败

**位置**：[`zjg_exporter.py:213`](file:///e:/TRAE_Project/MaterialManagementPro/squirrel_asset_manager/integration/zjg_exporter.py#L213)

```python
if ftn and os.path.isfile(ftn):
```

帧序列贴图的 `fileTextureName` 值通常包含帧号模式：
- `C:/path/to/texture.1001.exr` — 第一帧实际存在
- `C:/path/to/texture.####.exr` — 帧模式，`os.path.isfile()` 返回 False
- `<udim>` 模式（如 `texture.<UDIM>.exr`）同理

`os.path.isfile()` 对这些模式返回 `False`，导致贴图被跳过。

> **对比**：`asset_collector.py` 中已实现 `_resolve_frame_pattern()` 和 `_build_frame_sequence_from_single()` 处理帧序列，但贴图收集未复用此逻辑。

### 根因 5：displacement 上游贴图收集不完整

**位置**：[`zjg_exporter.py:221-236`](file:///e:/TRAE_Project/MaterialManagementPro/squirrel_asset_manager/integration/zjg_exporter.py#L221-L236)

当前对 displacement 的处理：
1. 通过 `shadingEngine.displacementShader` 找到 displacement 节点
2. 对 displacement 节点执行 `listHistory()`
3. 在 history 中搜索 `file` 类型节点

**问题**：
- 只查找了 `mat.outColor → shadingEngine` 这一种连接方式
- Redshift 的 displacement 可以通过 `RedshiftMaterial.displacement` 直接连接，不一定经过 `outColor → shadingEngine`
- Arnold 的 `aiStandardSurface.displacementShader` 直接连接 displacement 节点
- 多层 displacement 混合（displacement → blendColors → displacementShader）时可能漏收

### 根因 6：`_get_materials_from_objects` 可能遗漏特殊材质类型

**位置**：[`export_orchestrator.py:1067-1075`](file:///e:/TRAE_Project/MaterialManagementPro/squirrel_asset_manager/core/export_orchestrator.py#L1067-L1075)

从关联物体收集材质后，再收集贴图。但如果物体使用了以下非标准材质/着色器：
- `RedshiftVolumeMaterial`（体积材质）
- `RedshiftSprite`（精灵材质）
- `RedshiftHairShader`
- 多层材质（layeredShader）
- 材质覆盖（materialOverride）

这些材质的 shading 网络可能不同于 `outColor → shadingEngine` 的标准连接，导致材质未被正确识别，进而贴图也未被收集。

## 解决方案

### 方案 1：用「全属性递归扫描」替代 `listHistory`（核心改进）

**借鉴**：[`zjg_exporter.py:_serialize_node()`](file:///e:/TRAE_Project/MaterialManagementPro/squirrel_asset_manager/integration/zjg_exporter.py#L1292-L1341) 已有的全属性扫描逻辑

在 `_serialize_node` 中，已经有完善的节点图递归遍历：
- 对每个节点扫描所有属性（`_get_processable_attrs`）
- 对每个属性检查 `listConnections` 查找上游连接
- 递归遍历上游节点
- 能覆盖复合属性的子属性连接

**改进**：创建新的通用函数 `collect_all_texture_files(node)`：

```python
def collect_all_texture_files(root_node):
    """全属性递归扫描收集所有贴图文件路径。
    
    不再依赖 listHistory，而是递归遍历 shading 网络中
    每个节点的属性连接，匹配所有可能的贴图节点类型。
    """
    visited = set()
    texture_paths = set()
    
    def _traverse(node):
        if node in visited or not cmds.objExists(node):
            return
        visited.add(node)
        ntype = cmds.nodeType(node)
        
        # 1. 检查是否为贴图节点，提取路径
        path = _extract_file_path(node, ntype)
        if path:
            resolved = _resolve_or_expand_frame_pattern(path)
            for p in resolved:
                texture_paths.add(p)
        
        # 2. 扫描所有属性上的连接，递归上行
        try:
            all_attrs = cmds.listAttr(node) or []
            all_attrs += cmds.listAttr(node, hidden=True) or []
        except:
            all_attrs = cmds.listAttr(node) or []
        
        seen_attrs = set()
        for attr in sorted(set(all_attrs)):
            if attr in SKIP_ATTRS or attr.startswith('out'):
                continue
            # 跳过复合属性的子属性（R/G/B/X/Y/Z）
            if len(attr) >= 2 and attr[-1] in COMPOUND_CHILD_ENDS:
                continue
            
            try:
                conns = cmds.listConnections(f"{node}.{attr}", 
                                             source=True, destination=False)
                if conns:
                    for src in conns:
                        _traverse(src)
            except:
                pass
        
        # 3. 特殊处理：若是 shadingEngine，额外收集 displacement
        if ntype == 'shadingEngine':
            try:
                disp_conns = cmds.listConnections(f"{node}.displacementShader",
                                                  source=True, destination=False)
                if disp_conns:
                    for disp in disp_conns:
                        _traverse(disp)
            except:
                pass
    
    _traverse(root_node)
    return sorted(texture_paths)
```

**优势**：
- 不再依赖 `listHistory`，不会遗漏非历史连接
- 递归覆盖所有渲染器特定节点类型
- 自动处理复合属性的子属性连接
- 与 `_serialize_node` 采用一致的遍历策略

### 方案 4：帧序列贴图支持

复用 `asset_collector.py` 中已有的帧序列处理逻辑：

```python
def _resolve_texture_frame_pattern(path):
    """解析帧序列/UDIM 模式为实际文件列表。
    
    支持格式:
    - name.####.exr  → 展开为所有匹配帧
    - name.%04d.exr  → 同上
    - name.<UDIM>.exr → 展开为所有 UDIM tile
    - name.1001.exr  → 单帧（直接返回）
    
    返回: [文件绝对路径列表]
    """
    import glob
    import re
    
    if not path:
        return []
    
    # 单帧：直接检查
    if os.path.isfile(path):
        return [path]
    
    # 帧序列模式
    pattern = path.replace('####', '*').replace('%04d', '*').replace('%4d', '*')
    matches = sorted(glob.glob(pattern))
    if matches:
        return matches
    
    # UDIM 模式
    if '<UDIM>' in path or '<udim>' in path:
        udim_pattern = path.replace('<UDIM>', '*').replace('<udim>', '*')
        return sorted(glob.glob(udim_pattern))
    
    # 尝试父目录存在的情况（帧模式第一帧）
    parent = os.path.dirname(path)
    if os.path.isdir(parent):
        # 路径中存在 # 时做通配展开
        if '#' in path:
            wild = re.sub(r'#+', '*', os.path.basename(path))
            return sorted(glob.glob(os.path.join(parent, wild)))
    
    return []
```

### 方案 5：多路径来源的 displacement 全收集

不再仅依赖 `outColor → shadingEngine → displacementShader` 这一条路径：

```python
def _collect_displacement_textures(material_node):
    """全路径收集 displacement 上游的贴图"""
    paths = set()
    
    # 路径 1: shadingEngine.displacementShader (Maya 标准)
    try:
        ses = cmds.listConnections(f"{material_node}.outColor", 
                                   type='shadingEngine') or []
        for se in ses:
            disp_nodes = cmds.listConnections(f"{se}.displacementShader") or []
            for dn in disp_nodes:
                for tex in collect_all_texture_files(dn):
                    paths.add(tex)
    except:
        pass
    
    # 路径 2: 材质自身的 displacement 属性 (Redshift/Arnold)
    for disp_attr in ('displacement', 'displacementShader', 
                      'rsDisplacement', 'rsDisplacementShader'):
        try:
            conns = cmds.listConnections(f"{material_node}.{disp_attr}",
                                         source=True, destination=False)
            if conns:
                for src in conns:
                    for tex in collect_all_texture_files(src):
                        paths.add(tex)
        except:
            pass
    
    # 路径 3: bump 节点也常携带贴图
    for bump_attr in ('normalCamera', 'bumpMap', 'normal', 
                      'rsBumpMap', 'rsNormalMap'):
        try:
            conns = cmds.listConnections(f"{material_node}.{bump_attr}",
                                         source=True, destination=False)
            if conns:
                for src in conns:
                    for tex in collect_all_texture_files(src):
                        paths.add(tex)
        except:
            pass
    
    return sorted(paths)
```

## 风险评估

| 风险 | 缓解措施 |
|------|---------|
| 全属性递归扫描性能在超大型场景中可能较慢 | 使用 `visited` 集合避免重复遍历；限制递归深度 |
| 某些非贴图文件路径被误收集（如 .ass 代理路径） | 通过文件扩展名白名单过滤（`.exr`, `.hdr`, `.png`, `.jpg`, `.tif`, `.tga`, `.tx` 等） |
| 与现有 `_serialize_node` 逻辑重复 | 抽取公共遍历逻辑为独立函数，两个路径复用 |
