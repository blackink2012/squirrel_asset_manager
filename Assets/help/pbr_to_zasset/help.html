PBR贴图转资产工具 — 使用帮助

本工具将 PBR 贴图集合自动转换为 .zasset 资产格式，支持自动识别贴图类型、读取外部元数据（标签、描述等）、搜索已有缩略图。

1. 工具概述

工具可以帮你做这些事：

  • 自动识别贴图类型 — 根据文件名后缀自动辨认 BaseColor、Normal、Roughness 等 PBR 通道
  • 多分辨率支持 — 识别 2K/4K/8K 精度标记，打包时区分精度
  • 读取外部元数据 — 从 JSON/TXT 文件中提取 tags、description、author 等信息写入资产
  • 搜索已有缩略图 — 自动匹配 Megascans 的 *_Preview.png 或 Zoo Tools 的 */thumbnail.png
  • 批量转换 — 选择父文件夹，所有子文件夹各自打包为独立 .zasset
  • 直接入库 — 转换后可自动拷贝到当前资产库分类下

2. 贴图命名规则

工具通过文件名末尾或中间的下划线后缀来识别贴图属于哪个 PBR 通道。

基本格式：任意名称_通道别名.扩展名

PBR通道可用的别名（不区分大小写）正确示例错误示例
BaseColor（颜色） baseColor, base_color, albedo, diffuse, diff, col, color, base wood_albedo.png
砖墙_BaseColor.jpg
floor_4K_diff.tga		 woodcolor.png ❌ 缺下划线
baseColor.png ❌ 没有材质名
Normal（法线） normal, norm, nor, nrm, normalmap stone_normal.jpg
rock_nor_dx.png		 stone_N.jpg ❌ 太短没匹配
Roughness（粗糙度） roughness, rough, rgh metal_roughness.png metal_rough.png ❌ "rough" 不是别名
Metallic（金属度） metallic, metal, mtl steel_metallic.jpg
AO（环境光遮蔽） ao, ambientOcclusion brick_ao.png
Height（高度/置换） height, bump, displacement, displace, disp rock_displacement.exr
rock_displacement.jpg
Emissive（自发光） emissive, emiss, emit lava_emissive.png
要点：
  • 通道别名必须用下划线 _ 与前面的名称分隔
  • 分辨率标记 _2K_ / _4K_ 可以被正确识别并剥离（详见后面正则原理）
  • 同类型可以有多个文件（如 _Displacement.exr + _Displacement.jpg），都会被收集

3. 基本使用流程

单文件夹转换（最常用）

  1. 点击「浏览」选择包含 PBR 贴图的文件夹
  2. 设置输出文件夹（默认与输入文件夹相同）
  3. 点击「扫描贴图」— 工具会自动分析文件结构并在右侧显示识别结果
  4. 检查右侧树形列表：确认材质数量、贴图类型、精度是否正确
  5. 点击「转换」— 生成 .zasset 文件

3.1 批量模式

批量模式适用于：一个父文件夹下有多个子文件夹，每个子文件夹是一个独立的资产。例如 Megascans 下载后的结构：

surface/                          ← 选择这个父文件夹
├── bark_other_wknjchbs/          ← 子文件夹1 → 生成为 bark_other_wknjchbs.zasset
│   ├── wknjchbs_2K_Albedo.jpg
│   ├── wknjchbs_2K_Normal.jpg
│   ├── wknjchbs.json
│   └── wknjchbs_Preview.png
├── metal_sheet_xhtnbhlg/         ← 子文件夹2 → 生成为 metal_sheet_xhtnbhlg.zasset
│   └── ...
└── wood_veneer_vlsjeec/          ← 子文件夹3
    └── ...
  1. 勾选「批量模式」复选框
  2. 选择父文件夹（包含多个子文件夹的目录）
  3. 点击「扫描贴图」— 所有子文件夹被逐一扫描
  4. 点击「转换」— 每个子文件夹生成一个独立的 .zasset

3.2 递归扫描子文件夹中的贴图

默认情况下，工具只扫描所选文件夹根目录下的贴图文件。如果贴图被放到了子文件夹里（如 tex/ 目录），需要开启递归扫描。

适用场景：

  • 贴图文件在 tex/ 或 textures/ 子目录下
  • 贴图按分辨率分目录存放（tex/2K/、tex/4K/）
  • 资产有多层子文件夹结构

三种模式

模式行为适用场景
关闭（默认） 只扫描根目录文件 贴图直接放在文件夹根目录（如 Megascans 原始格式）
自动递归全部 递归所有子文件夹（无限层级），跳过排除列表中的文件夹 不确定子文件夹名称，或有多层嵌套结构
手动指定 只递归指定名称的子文件夹（如 tex），进入后自动递归其所有子目录 知道贴图在哪个文件夹下，想避免扫描无关目录

排除目录

在「排除」输入框中填写要跳过的文件夹名（逗号分隔），例如：

Thumbs, previews, .mayaSwatches

递归时会自动跳过这些文件夹，避免把缩略图目录或缓存目录里的图片误识别为贴图。

实际案例

案例1：贴图在 tex/ 目录下（平铺）

└── tex/
    ├── brick_2K_Albedo.jpg

        └── ...

5. 配置详解

工具通过 pbr_mapping.json 配置文件来定义「如何找到缩略图」「如何找到元数据文件」「元数据中哪些字段映射到哪里」。点工具右上角的「设置」标签页即可编辑。

5.1 变量占位符 {folderName} 与 {materialName}

这是配置中最重要的两个变量，它们会被自动替换成实际名称：

占位符替换成什么举例（文件夹 metal_sheet_xhtnbhlg，贴图提取出材质名 xhtnbhlg）
{folderName} 文件夹的名称 {folderName}.json → metal_sheet_xhtnbhlg.json
{materialName} 从贴图文件名中提取出的材质名
例如 xhtnbhlg_2K_Albedo.jpg 剥离精度和通道后得到 xhtnbhlg		 {materialName}_Preview.png → xhtnbhlg_Preview.png
搜索规则（重要）：工具会优先用 {materialName} 匹配，找不到文件时再自动回退用 {folderName}。所以你不需要纠结用哪个 — 配置里写哪个占位符都行，工具会两种都试一遍。

建议：用 {materialName} 写路径模板，因为如果找到了按材质名命名的文件（如 Megascans 的 xhtnbhlg.json），就不需要再尝试文件夹名。

5.2 文件路由配置

文件路由控制「源文件夹中哪些扩展名的文件」打包到「.zasset 内部的哪个位置」。

字段含义示例
文件夹 .zasset 内部的目标目录名
root 表示放在根目录		 textures
扩展名 要被路由的文件扩展名（空格分隔） .png .jpg .exr .hdr
工作原理：扫描文件夹时，所有匹配扩展名的文件都会被找到。PBR 贴图（匹配了通道别名的）会走专门的贴图打包流程（按分辨率分目录）；其余匹配了扩展名但不属于 PBR 通道的文件（如 .ma .mb 模型文件）会按路由规则放入对应子目录。

例如路由配置：root → .ma .mb，则 Maya 文件会放在 .zasset 根目录。

5.3 缩略图搜索路径

定义从哪里找已有缩略图。工具会依次尝试每一条路径模板，替换 {materialName} 和 {folderName}，找到第一个存在的文件就使用。

场景推荐配置实际匹配的文件路径
Megascans 资产 {materialName}_Preview.png xhtnbhlg_Preview.png
Zoo Tools 资产 {folderName}_ma_fileDependencies/thumbnail.png myMat_ma_fileDependencies/thumbnail.png
如果所有路径都找不到缩略图，工具会回退使用 BaseColor/Diffuse 贴图自动生成缩略图。不需要缩略图的话可以留空。

5.4 元数据源配置

这是本工具最强大的功能之一：从外部 JSON 或 TXT 文件中读取字段，自动写入 .zasset 的元数据。

什么场景需要？

  • Megascans 每个资产目录下都有 *.json 文件，包含 tags、name 等信息
  • 从 Zoo Tools 导出的资产有 .zooInfo JSON 文件
  • 你自己为资产写了描述文件（如 info.json 或 readme.txt）

每条元数据源需要配置三个部分：

配置项说明示例值
文件路径模板 元数据文件在资产文件夹中的位置，用 {materialName} 或 {folderName} 占位 {materialName}.json
文件格式 json 或 txt json
字段映射 将源文件中的字段名，映射到 .zasset 的目标字段，可选处理器转换格式 见下方详细说明

字段映射是逐条定义的，每条包含：

  • 源字段 — JSON 文件中的键名（如 "tags"、"name"、"description"）
  • 目标字段 — 写入 .zasset 的字段名（通常与源字段同名即可）
  • 处理器 — 可选，对读取到的值做格式转换（见 5.5）

目标字段有哪些可用？

目标字段名含义值的格式
tags资产标签列表字符串数组，如 ["metal", "rust", "old"]
description资产描述文本纯文本字符串
author作者名称纯文本字符串
source_url来源 URL纯文本字符串

5.5 字段处理器 — 数据格式转换

处理器的作用是：将源文件中读到的值，转换成 .zasset 需要的格式。

处理器做什么什么时候用
none 什么都不做，原样保留 最常用。源数据格式已经正确（如 Megascans 的 tags 已经是一个数组，直接可用）
split_comma 把 逗号分隔的字符串 切成数组 只有源数据中的 tags 存成了 "metal, wood, glass" 这种字符串时才用
first_line 只取第一行 源数据是多行文本（如 txt 文件），只需第一行做描述
⚠ 最常犯的错误：源数据中的 tags 已经是 ["a","b","c"]（JSON 数组）了，却选了 split_comma。
这会导致程序崩溃（list 不能 .split(',')），元数据读取失败返回空。

简单判断方法：打开 JSON 文件看一眼 — tags 是带方括号的 ["...","..."] 就用 none；是用双引号括起来的一串 "a, b, c" 就用 split_comma。

5.6 内部工作原理 — 贴图文件名正则匹配

这一节解释工具内部怎么识别贴图 — 你不需要手动写正则，但了解原理有助于排查命名不匹配的问题。

贴图类型识别（identify_texture_type）的匹配优先级：

优先级=1（最高）：文件名以 _别名 结尾
  例：wood_albedo.jpg  → "_albedo" 匹配 baseColor 别名 ✓

优先级+5：文件名包含 _分辨率_别名 模式
  例：floor_2K_diff.png → 剥离 "_2K" 后 floor_diff 匹配 diff 别名 ✓

优先级+10：文件名包含 _别名_ 中间匹配
  例：rock_diff_2K.jpg → 匹配 diff 别名 ✓

分辨率剥离（detect_resolution_from_name）：

输入：xhtnbhlg_2K_Albedo
       ↓ 识别到 "_2K_" 中间模式
       ↓ 只移除 "2K" 文本本身（保留前后 _）
输出：xhtnbhlg_Albedo  +  分辨率="2K"

材质名提取（extract_material_name）：

输入：xhtnbhlg_Albedo  +  通道别名 "albedo"
       ↓ 移除末尾的 _albedo
输出：xhtnbhlg

所以从 xhtnbhlg_2K_Displacement.exr 到最终数据的完整流程：

xhtnbhlg_2K_Displacement.exr
  → 分辨率剥离 → xhtnbhlg_Displacement (res=2K)
    → 通道识别 → "displacement" 匹配 height 别名
      → 材质名提取 → xhtnbhlg
        → 存入: resolution_map["xhtnbhlg"]["variants"]["2K"]["height"]
文件名大小写不敏感：Albedo、ALBEDO、albedo 都会匹配。
分辨率大小写保留：2K 保持为 2K（不会变成小写 2k）。

7. 常见问题

❌ 扫描后显示 "未发现有效的PBR贴图"

检查以下几点：

  • 文件名中是否有下划线 + 别名？（如 _albedo、_normal）
  • 文件名是否太短？至少要有 "材质名_别名.扩展名"
  • 扩展名是否在文件路由配置的扩展名列表中？

❌ 元数据没有被读取（tags 为空、没有 description）

按以下顺序排查：

  1. 文件路径模板是否正确？ — 在资产文件夹里按模板拼接的路径能定位到那个 JSON 文件吗？不确定的话在文件管理器里验证一下
  2. 占位符用对了吗？ — 如果 JSON 文件叫 xhtnbhlg.json（按贴图材质名命名），用 {materialName}.json；如果叫 folderName.json，用 {folderName}.json
  3. 源字段名与 JSON 键名一致吗？ — JSON 里是 "name"，你映射的源字段也要写 name
  4. 处理器选对了吗？ — 对 list 用 split_comma 会崩溃（见 5.5）

❌ 缩略图没有生成（或显示占位图）

  • 检查缩略图搜索路径是否匹配（模板拼接后的路径文件存在吗？）
  • 如果源文件有 BaseColor/Diffuse 贴图，工具会用颜色贴图自动生成缩略图。没有颜色贴图则无法生成

❌ 分辨率（2K/4K/8K）没有被分离

  • 文件名中的分辨率标记要符合 _2K_、_4K_ 等格式（注意大写 K）
  • 如果分辨率只在子文件夹名中（如 2K/ 目录），不会被识别 — 文件名本身需包含分辨率标记

❌ 批量模式下某个文件夹被跳过

批量为空文件夹或有子文件夹但不含有效 PBR 贴图的会被跳过。可以在扫描结果中查看具体哪些文件夹被识别到了。
