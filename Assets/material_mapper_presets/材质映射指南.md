# 材质映射指南（.mmap）

本文件总结「材质节点属性映射工具 / 材质转换工具」使用 `.mmap` 映射文件的核心知识，包括文件格式、引擎执行规则、openPBRSurface / aiStandardSurface → VRayMtl 的推荐映射，以及实战中踩过的坑。

***

## 1. 文件格式

映射文件为 JSON，命名约定 `{源类型}_{目标类型}.mmap`，存放在 `material_mapper_presets/` 下。

```json
{
    "version": "3.0",
    "name": "openPBRSurface → VRayMtl",
    "software": "maya",
    "source_type": "openPBRSurface",
    "target_type": "VRayMtl",
    "description": "openPBRSurface 到 VRayMtl 的属性映射",
    "created_date": "2026-08-26",
    "mappings": [
        {
            "source_attribute": "baseColor",
            "target_attribute": "color",
            "transform": "",
            "default_value": ""
        }
    ]
}
```

`mappings` 每个条目的字段：

| 字段                 | 含义                                                            |
| ------------------ | ------------------------------------------------------------- |
| `source_attribute` | 源材质属性名。**为空字符串**表示「无源」——用于把目标属性重置为默认值。                        |
| `target_attribute` | 目标材质属性名。**为空字符串**表示该映射被跳过（仅保留记录，不执行）。                         |
| `transform`        | 转换函数英文标识（见第 3 节）。无需转换时填空字符串 `""`。                             |
| `default_value`    | 源属性缺失/无值时的兜底值，如 `"1.0"`、`"(1.0, 1.0, 1.0)"`。                  |
| `parameters`       | 转换函数的额外参数（可选），如 `clamp` 的 `{"min_val": 0.0, "max_val": 1.0}`。 |

***

## 2. 引擎执行规则（材质转换工具.py convert\_material）

按 `mappings` 顺序逐条执行，规则如下：

1. **`target_attribute`** **为空 → 直接跳过**（不执行）。
2. **目标属性在目标材质上不存在 → 记失败并跳过**。
3. **颜色子通道目标 → 无条件跳过**（关键！）：
   - 判定：目标属性以 `R`/`G`/`B` 结尾，且去掉末尾字母后的父属性真实存在（如 `diffuseColorR` → 父 `diffuseColor`）。
   - 原因：渲染器材质的颜色子通道常与父颜色属性别名共享，单独写子通道会覆盖整体颜色导致通道丢失。
   - **结论：颜色必须映射到父属性**（`color` / `diffuseColor` / `reflectionColor` / `refractionColor` / `fogColor` / `translucencyColor` / `sheenColor` / `coatColor` / `illumColor` / `opacityMap` 等），`rgb_to_red` 之类的通道变换**不要用于颜色目标**。
4. **源属性存在且有贴图连接**（且启用贴图复制）→ 自动建立目标属性上的贴图连接（`_connect_texture` / `_connect_texture_transform`）。
5. **源属性缺失或取值为空 → 使用** **`default_value`**；若 `default_value` 也为空，则读取目标属性当前值重新写回（等效「重置为默认」）。这就是「空 source + 非空 target」条目作为重置项的原理。
6. **写值规则**：
   - `float3`/颜色列表 → 走稳健的多方案颜色写入（写父属性，不回读校验子通道）。
   - 标量写颜色属性 → **自动广播为 RGB 相同值**。
   - 布尔/数值/字符串按类型写入；写前自动断开目标上的输入连接，避免「已锁定或已连接」。

## 3. 转换函数（transform）

| 英文标识                                                             | 用途                               | 反向函数（自动用于反向转换）                   |
| ---------------------------------------------------------------- | -------------------------------- | -------------------------------- |
| `rgb_to_channel` / `rgb_to_red` / `rgb_to_green` / `rgb_to_blue` | 提取颜色单通道                          | —                                |
| `roughness_to_shininess`                                         | PBR 粗糙度 → 光泽度（1-x）               | `shininess_to_roughness`         |
| `diffuse_roughness_to_roughness`                                 | 漫反射粗糙度 → PBR 粗糙度（当前恒等）           | `roughness_to_diffuse_roughness` |
| `specular_to_specular_weight`                                    | 镜面强度 → 权重（钳制 0-1）                | 同名反向                             |
| `transparency_to_transmission`                                   | 透明度 → 透射权重（当前恒等）                 | `transmission_to_transparency`   |
| `translucence_to_subsurface`                                     | 半透明 → 次表面权重                      | 同名反向                             |
| `emission_to_emission_luminance`                                 | 自发光 → 发光亮度                       | 同名反向                             |
| `clamp`                                                          | 钳制到 `[min_val, max_val]`（默认 0-1） | —                                |

> 正向/反向转换共用同一 `.mmap`：反向时引擎自动套用 `TRANSFORM_REVERSE` 中的反向函数（如 VRayMtl → openPBRSurface 时 `reflectionGlossiness` → `specularRoughness` 会走 `shininess_to_roughness`）。

## 5. 常见错误与实战教训

### 5.1 颜色映射写子通道（最易犯、后果最重）

把 `baseColor` 映射到 `diffuseColorR` 并加 `rgb_to_red` —— 引擎会判定为颜色子通道目标而**整条跳过**，颜色和贴图全部丢失。**颜色一律写父属性、不加通道变换。**

### 5.2 以 R/G/B/A/X/Y/Z 结尾的属性名陷阱（zmetal 导出相关）

属性名本身以这些字母结尾（如 `coatIOR`、`specularIOR`、`thinFilmIOR`）容易被「复合属性子通道推断」逻辑误判：Maya 的 `listAttr(every=True)` 返回叶子属性，导出代码需把 `colorR` 这类子通道归并回父属性 `color`，但**必须先确认父属性真实存在**（`cmds.objExists`），否则 `coatIOR` 会被截断成 `coatIO` 而整体丢失，导致 zmetal 缺失 IOR 属性、导入后回落为渲染器默认值（如 openPBRSurface 的 `coatIOR` 默认 1.6，与 .ma 显式的 1.5 不一致）。

### 5.3 语义错乱映射示例（AI 生成映射的典型错误）

- `aiMatteColor` → `illumColor`：遮罩颜色 ≠ 自发光颜色。
- `indirectDiffuse` → `diffuseColorG`：GI 权重 ≠ 漫反射绿通道。
- `subsurfaceScale` → `bumpDeltaScale`：SSS 半径 ≠ 凹凸增量。
- `subsurfaceAnisotropy` → `anisotropyDerivation`：SSS 各向异性 ≠ 高光方向枚举。
- `coatAffectRoughness` → `reflectionAffectAlpha`：涂层粗糙度影响 ≠ 反射影响 Alpha。
- `transmissionDispersion`(bool) → `refrDispersionAbbe`(float)：类型不匹配，应映射到 `refrDispersionOn`。
- `subsurfaceType` → `translucencyMode`：两侧枚举含义与数值不对应。

### 5.4 检查清单

1. 所有颜色目标是否为父属性（非 R/G/B 结尾）。
2. 源属性名在目标渲染器对应节点上真实存在（警惕 `aiMatteColorA` 这类编造的子属性）。
3. 布尔 ↔ 浮点、颜色 ↔ 浮点是否错配。
4. 枚举类型是否含义对应（不确定就跳过）。
5. 目标侧未覆盖的属性是否需要「重置为默认」条目。
6. 反向转换是否成立（`transform` 是否有反向函数）。
7. 修改后校验 JSON：`python -c "import json;json.load(open('xxx.mmap',encoding='utf-8'))"`。
