Material Node Attribute Mapper

For Maya 2022+ · PySide6 / PySide2

The Material Node Attribute Mapper builds attribute mapping relationships between different material node types in Maya: map attributes of a source material (e.g., Arnold's aiStandardSurface) to the corresponding attributes of a target material (e.g., V-Ray's VRayMtl), optionally attaching a transform function (such as shininess-to-roughness) and a default value. It supports manual row-by-row configuration, AI-assisted mapping for automatic inference, and saving / loading / reusing .mmap presets.

1. Interface Layout

1.1 Top Toolbar

  • Add Row: appends a mapping row; if the source/target node types are set, automatically fetches that node type's readable/writable visible attributes as drop-down options.
  • Remove Selected: deletes the selected rows from the table.
  • Attribute Browser: browses the available attributes of the currently selected object in Maya and fills them into the current row (select an object in Maya first).
  • AI Smart Mapping: invokes AI to infer the target attribute / transform function / default value for all source attributes in the table.
  • Help: opens this help document.
  • Save Preset / Load Preset: saves the current mapping as a .mmap file, or loads a mapping from a file.

1.2 Node Type Area

  • Source Node: select a source material node in Maya and click "Load" to auto-detect its type and populate the source attribute list; "Clear Source" resets it.
  • Target Node: load the target node the same way; there is also a "Load Default Values" button that fills the current values of the target attributes into the "Default Value" column (select a target node of the matching type in Maya first).

1.3 AI Service Configuration

  • AI Service: drop-down to choose a provider — Ollama (Local) / DeepSeek / Qwen (Alibaba Cloud DashScope).
  • API Key: not required for local Ollama; DeepSeek / Qwen require the platform API Key (stored as a password field).
  • AI Model: editable combo box to select or manually type a model name; click "Refresh" to pull the available model list from the provider.

1.4 Mapping Table

Five columns: Select / Source Attribute / Target Attribute / Transform Function / Default Value. Supports multi-row selection and a right-click context menu (per-row AI inference / clear cell, etc.).

1.5 Search & Bottom Action Bar

  • Search box: filters table rows in real time by keyword.
  • Preset path: shows the preset directory; "Open Folder" jumps to it.
  • Reverse Mapping: one-click swap of source/target node types and table attributes.
  • Clear Table: clears all mapping rows.
  • Load Sample Data: fills in a set of built-in examples for a quick start.

2. Quick Start

  1. Select the source material node in Maya and click "Load" under Source; then select the target material node and click "Load" under Target.
  2. The table's drop-downs are automatically populated with both node types' attributes; you can also use the Attribute Browser or manually add/edit rows.
  3. For each source attribute, specify the target attribute, the transform function (if needed) and the default value (click "Load Default Values" to bulk-fetch current values).
  4. Click "Save Preset" to store the mapping as a .mmap file; next time use "Load Preset" to reuse it.
Auto-remember: closing the window auto-saves to _last_preset.mmap, and the tool auto-restores the last mapping configuration on next launch.

3. AI Smart Mapping

Steps

  1. Make sure the source/target node types are loaded and the table already contains source attribute rows.
  2. In "AI Service", choose a provider: local Ollama, DeepSeek, or Qwen; cloud services require an API Key.
  3. Select a model (click "Refresh" to fetch the available model list) and confirm the AI service is reachable.
  4. Click "AI Smart Mapping". The tool reads the source/target node types, the source attribute list, the available target attribute list and the transform function list, asks the LLM to infer "target attribute" and "transform function" for each item, fills the table automatically, and you can fine-tune afterwards.
Per-row AI inference: right-click a row in the table to run AI inference for that row only, without mapping the whole table.

Ollama Local Usage Notes

  • Install and start Ollama, and run ollama pull for the model you want (default endpoint http://localhost:11434).
  • The default model is qwen3-vl:8b. If it is not pulled locally, pick an installed model from the drop-down (e.g., qwen3.5:4b) or run ollama pull qwen3-vl:8b.
  • qwen3-series models are reasoning models and output a chain-of-thought first by default. The tool automatically switches to the Ollama native API and disables thinking (think=false) so that the JSON result is returned directly.

5. Preset Files

  • Presets use the .mmap format (JSON), stored by default in Assets/material_mapper_presets, named sourceType_targetType.mmap.
  • A preset contains the source/target node types, the creation date and the full mapping list, making it easy to share mapping schemes within a team.
  • Click "Open Folder" to view the preset directory directly.

6. FAQ

6.1 "AI did not return valid mapping results"

  • Local Ollama: make sure the service is running and the selected model has been pulled (ollama pull); try "Refresh" to update the model list and reselect.
  • Cloud services: check the API Key and whether the network can reach the provider.
  • If there are too many source attributes the LLM may time out; run per-row / partial AI mapping instead.
  • If you see [OllamaMapper] logs in the Maya Script Editor, use them to inspect the response for troubleshooting.

6.2 "Cannot connect to AI service"

For Ollama, confirm the local service is running (browsing http://localhost:11434 responds); for cloud services, check the API Key and network settings.

6.3 Empty attribute drop-down lists

Confirm the source/target node types have been loaded via "Load"; node types without visible writable attributes may produce empty lists — use the Attribute Browser to add attributes one by one instead.
