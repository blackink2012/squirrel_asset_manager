PBR Textures to Asset Tool — Help

This tool automatically converts a set of PBR textures into the .zasset asset format. It supports automatic texture-type recognition, reading external metadata (tags, description, etc.), and searching for existing thumbnails.

1. Tool Overview

Here is what the tool can do for you:

  • Auto-detect texture type — recognize BaseColor, Normal, Roughness and other PBR channels from the file name suffix
  • Multi-resolution support — recognize 2K/4K/8K resolution markers and separate resolutions when packing
  • Read external metadata — extract tags, description, author and more from JSON/TXT files and write them into the asset
  • Search existing thumbnails — automatically match Megascans' *_Preview.png or Zoo Tools' */thumbnail.png
  • Batch conversion — choose a parent folder so each subfolder becomes a separate .zasset
  • Direct library import — auto-copy into the current asset library category after conversion

2. Texture Naming Rules

The tool identifies which PBR channel a texture belongs to by the underscore suffix at the end or middle of the file name.

Basic format:AnyName_channelAlias.extension

PBR ChannelAvailable Aliases (case-insensitive)Valid ExamplesInvalid Examples

brickwall_BaseColor.jpg

baseColor.png ❌ no material name
Normal normal, norm, nor, nrm, normalmap stone_normal.jpg

Key points:
  • The channel alias must be separated from the preceding name with an underscore _
  • Resolution markers like _2K_ / _4K_ are recognized and stripped correctly (see the regex section below)
  • Multiple files of the same type are allowed (e.g. _Displacement.exr + _Displacement.jpg) and are all collected

3. Basic Workflow

Single-folder Conversion (most common)

  1. Click "Browse" and choose the folder containing the PBR textures
  2. Set the output folder (by default the same as the input folder)
  3. Click "Scan Textures" — the tool auto-analyzes the file structure and shows recognition results on the right
  4. Check the tree list on the right: confirm material count, texture types, and resolutions are correct
  5. Click "Convert" — generates the .zasset file

3.1 Batch Mode

Batch mode is for the case where a parent folder contains multiple subfolders, and each subfolder is an independent asset. For example, the structure after downloading from Megascans:

surface/                          ← select this parent folder
├── bark_other_wknjchbs/          ← subfolder 1 → generated as bark_other_wknjchbs.zasset
│   ├── wknjchbs_2K_Albedo.jpg
│   ├── wknjchbs_2K_Normal.jpg
│   ├── wknjchbs.json
│   └── wknjchbs_Preview.png
├── metal_sheet_xhtnbhlg/         ← subfolder 2 → generated as metal_sheet_xhtnbhlg.zasset
│   └── ...
└── wood_veneer_vlsjeec/          ← subfolder 3
    └── ...
  1. Check the "Batch Mode" checkbox
  2. Select the parent folder (a directory containing multiple subfolders)
  3. Click "Scan Textures" — every subfolder is scanned one by one
  4. Click "Convert" — each subfolder generates an independent .zasset

3.2 Recursively Scanning Textures in Subfolders

By default, the tool only scans texture files in the selected folder's root directory. If textures are placed in subfolders (e.g. a tex/ directory), you need to enable recursive scanning.

When do you need it?

  • Texture files live under a tex/ or textures/ subfolder
  • Textures are organized into per-resolution folders (tex/2K/, tex/4K/)
  • The asset has a multi-level subfolder structure

Three Modes

ModeBehaviorBest For
Off (default) Only scans files in the root folder Textures sit directly in the folder root (e.g. raw Megascans layout)
Auto-recurse all Recurses into all subfolders (unlimited depth), skipping folders in the exclude list You don't know subfolder names, or there is deep nesting
Manual specify Only recurses into subfolders with the given names (e.g. tex), then recurses all their subfolders automatically You know where the textures are and want to avoid scanning unrelated folders

Excluded Directories

In the "Exclude" input box, enter folder names to skip (comma-separated), for example:

Thumbs, previews, .mayaSwatches

During recursion these folders are automatically skipped, so images in thumbnail or cache directories are not mistaken for textures.

5. Configuration Details

The tool uses the pbr_mapping.json config file to define "how to find thumbnails", "how to find metadata files", and "which fields in the metadata map where". You can edit it in the "Settings" tab at the top-right of the tool.

5.1 Variable Placeholders {folderName} and {materialName}

These are the two most important variables in the config. They are automatically replaced with real names:

PlaceholderWhat it is replaced withExample (folder metal_sheet_xhtnbhlg, material name xhtnbhlg extracted from the textures)
{folderName} The name of the folder {folderName}.json → metal_sheet_xhtnbhlg.json
{materialName} The material name extracted from the texture file names
e.g. xhtnbhlg_2K_Albedo.jpg strips the resolution and channel to get xhtnbhlg		 {materialName}_Preview.png → xhtnbhlg_Preview.png
Search rules (important): the tool first tries to match with {materialName}, and if no file is found it automatically falls back to {folderName}. So you don't need to worry about which one to use — either placeholder works, the tool tries both.

Recommendation: use {materialName} in path templates, because if a file named after the material is found (e.g. Megascans' xhtnbhlg.json), the folder name no longer needs to be tried.

5.2 File Routing Configuration

File routing controls "which file extensions from the source folder" are packed into "which location inside the .zasset".

FieldMeaningExample
Folder The target directory name inside the .zasset
root means the root directory		 textures
Extensions File extensions to route (space-separated) .png .jpg .exr .hdr
How it works: when scanning a folder, all files matching the extensions are found. PBR textures (that matched a channel alias) go through the dedicated texture packing flow (grouped by resolution); the remaining files that match the extensions but are not PBR channels (e.g. .ma .mb model files) are placed into the corresponding subdirectory according to the routing rules.

For example with routing config root → .ma .mb, Maya files are placed in the .zasset root directory.

5.3 Thumbnail Search Paths

Defines where to look for existing thumbnails. The tool tries each path template in turn, replacing {materialName} and {folderName}, and uses the first file it finds.

ScenarioRecommended ConfigMatched File Path
Megascans assets {materialName}_Preview.png xhtnbhlg_Preview.png
Zoo Tools assets {folderName}_ma_fileDependencies/thumbnail.png myMat_ma_fileDependencies/thumbnail.png
If no path finds a thumbnail, the tool falls back to auto-generating a thumbnail from the BaseColor/Diffuse texture. If you don't need thumbnails you can leave this empty.

5.4 Metadata Source Configuration

This is one of the tool's most powerful features: it reads fields from an external JSON or TXT file and automatically writes them into the .zasset metadata.

When do you need it?

  • Megascans has a *.json file in every asset directory, containing tags, name, and more
  • Assets exported from Zoo Tools have a .zooInfo JSON file
  • You wrote a description file for your own asset (e.g. info.json or readme.txt)

Each metadata source requires three parts:

Config ItemDescriptionExample Value
File Path Template The location of the metadata file within the asset folder, using {materialName} or {folderName} placeholders {materialName}.json
File Format json or txt json
Field Mapping Maps the field names from the source file to the target fields of the .zasset, with an optional processor to transform the format See details below

Field mappings are defined one by one; each consists of:

  • Source field — a key name in the JSON file (e.g. "tags", "name", "description")
  • Target field — the field name written to the .zasset (usually the same as the source field)
  • Processor — optional, transforms the read value (see 5.5)

Which target fields are available?

Target Field NameMeaningValue Format
tagsAsset tag listArray of strings, e.g. ["metal", "rust", "old"]
descriptionAsset description textPlain text string
authorAuthor namePlain text string
source_urlSource URLPlain text string

5.5 Field Processors — Data Format Conversion

The purpose of a processor is to transform the value read from the source file into the format the .zasset needs.

ProcessorWhat it doesWhen to use
none Does nothing, keeps the value as-is Most common. The source data format is already correct (e.g. Megascans tags are already an array and ready to use)
split_comma Splits a comma-separated string into an array Only when the source tags are stored as a string like "metal, wood, glass"
first_line Takes only the first line The source is multi-line text (e.g. a txt file) and only the first line is needed as a description
⚠ Most common mistake: the source tags are already ["a","b","c"] (a JSON array), but you select split_comma.
This crashes the program (a list cannot call .split(',')), and metadata reading fails returning an empty result.

Simple way to tell: open the JSON file and look — if tags are bracketed ["...","..."], use none; if they are a quoted string "a, b, c", use split_comma.

5.6 How It Works Internally — Texture File Name Regex Matching

This section explains how the tool recognizes textures internally — you don't need to write regex by hand, but understanding it helps troubleshoot naming mismatches.

Texture type detection (identify_texture_type) matching priority:

Priority=1 (highest): file name ends with _alias
  e.g. wood_albedo.jpg  → "_albedo" matches baseColor alias ✓

Priority+5: file name contains _resolution_alias pattern
  e.g. floor_2K_diff.png → after stripping "_2K", floor_diff matches diff alias ✓

Priority+10: file name contains _alias_ in the middle
  e.g. rock_diff_2K.jpg → matches diff alias ✓

Resolution stripping (detect_resolution_from_name):

Input: xhtnbhlg_2K_Albedo
       ↓ detects the "_2K_" middle pattern
       ↓ removes only the "2K" text itself (keeps the surrounding _)
Output: xhtnbhlg_Albedo  +  resolution="2K"

Material name extraction (extract_material_name):

Input: xhtnbhlg_Albedo  +  channel alias "albedo"
       ↓ removes the trailing _albedo
Output: xhtnbhlg

So the full flow from xhtnbhlg_2K_Displacement.exr to the final data:

xhtnbhlg_2K_Displacement.exr
  → resolution stripped → xhtnbhlg_Displacement (res=2K)
    → channel detection → "displacement" matches height alias
      → material name extraction → xhtnbhlg
        → stored: resolution_map["xhtnbhlg"]["variants"]["2K"]["height"]
File names are case-insensitive: Albedo, ALBEDO, and albedo all match.
Resolution case is preserved: 2K stays 2K (not lowercased to 2k).

7. FAQ

❌ After scanning it shows "No valid PBR textures found"

Check the following:

  • Does the file name contain underscore + alias? (e.g. _albedo, _normal)
  • Is the file name too short? It needs at least "materialName_alias.extension"
  • Is the extension listed in the file routing config's extension list?

❌ Metadata was not read (tags empty, no description)

Troubleshoot in this order:

  1. Is the file path template correct? — Does the path built from the template locate that JSON file in the asset folder? If unsure, verify it in the file manager
  2. Are the placeholders right? — if the JSON file is named xhtnbhlg.json (named after the texture material), use {materialName}.json; if it is called folderName.json, use {folderName}.json
  3. Does the source field name match the JSON key? — if the JSON has "name", your mapped source field must also be name
  4. Is the processor correct? — using split_comma on a list crashes (see 5.5)

❌ The thumbnail was not generated (or shows a placeholder)

  • Check whether the thumbnail search path matches (does the file at the template-built path exist?)
  • If the source has a BaseColor/Diffuse texture, the tool auto-generates a thumbnail from the color texture. Without a color texture it cannot generate one

❌ Resolutions (2K/4K/8K) were not separated

  • Resolution markers in file names must match the _2K_, _4K_, etc. format (note the capital K)
  • If the resolution only exists in the subfolder name (e.g. a 2K/ directory), it is not recognized — the file name itself must contain the resolution marker

❌ A folder is skipped in batch mode

Empty folders, or folders with subfolders but no valid PBR textures, are skipped. You can see exactly which folders were recognized in the scan results.
