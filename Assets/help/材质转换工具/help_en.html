Material Converter — Help

This tool is used to batch convert between material types in Maya, with support for custom mapping relationships. It can handle material replacement in large scenes (e.g., converting all lambert materials to aiStandardSurface).

1. Overview

This tool can help you:

  • Batch conversion — convert all matching materials in the scene at once, or only the selected materials
  • Type mapping — define correspondences from source material types to target material types, with dropdown selection for both
  • Attribute mapping — control attribute transfer via .mmap mapping files
  • openPBR intermediate — when no direct mapping exists, automatically convert through the openPBR intermediate format
  • Failure handling — failed materials are skipped automatically and reported; you can select them in Maya with one click
  • Default material fallback — optional: create a basic target-type material when no mapping file is found
  • Preset saving — reuse common mapping configurations via .mlist files

2. Workflow

2.1 Configure Material Type Mappings

  1. In the "Material Type Mapping Configuration" table, add mapping rows from source material type to target material type
  2. Source/Target cells are dropdowns: options are collected automatically from the .mmap files in the mapping folder (the convertible types); you can also type a custom type directly
  3. Alternatively, use "Load Source" / "Load Target" buttons to load the type from a selected material node
  4. When there is a single row with an empty source, all materials are converted to that target type
  5. Click "Save Preset" to store the current configuration as a .mlist file

2.2 Select Mapping Files

  1. The mapping file area is at the top of the window: click "Browse..." to choose the folder containing the .mmap mapping files
  2. Below it, the mapping folder path is displayed; click "Open Folder" to open it in the file explorer
  3. The tool automatically loads all .mmap files from the folder and matches them by "source material type" and "target material type"
Tip: .mmap mapping files can be created and managed with the "Material Node Attribute Mapping" tool.

2.3 Run the Conversion

  1. After configuring the mappings, click "Convert Selection" — converts only the selected materials
  2. Or click "Convert All" — converts every material matching the mapping configuration in the scene
  3. The conversion path is resolved automatically: a direct mapping file (A→B) is preferred; if none is found, the tool tries an openPBR intermediate path (A→openPBR→B)
  4. Progress is shown in the status bar at the bottom
  5. When finished, a dialog reports the number of succeeded/failed materials; failed ones can be selected with one click
Note: It is recommended to save the scene before converting. Backing up before batch operations is a good habit.

3. Interface Guide

3.1 Mapping File Area (Top)

Located at the top of the window, it has two rows:

  • Row 1: mapping file path (read-only) + "Browse..." button + status label
  • Row 2: mapping folder directory path + "Open Folder" button

3.2 Mapping Config Table

Defines the "source material type → target material type" correspondences:

  • Source: the material type to convert (e.g. lambert, phong, blinn), select from dropdown or type
  • Target: the resulting material type (e.g. aiStandardSurface, redshiftStandardMaterial), select from dropdown or type

Button row below the table:

4. openPBR Intermediate Conversion

Converting materials between different renderers depends on .mmap mapping files. To avoid the explosion of mapping files for every A→B combination, the tool uses the openPBR intermediate format:

  • You only need mappings such as A→openPBR, openPBR→A, B→openPBR, openPBR→B
  • When the user wants A→B but no direct mapping file exists, the tool automatically runs A→openPBR then openPBR→B
  • Intermediate openPBR materials created during the process are cleaned up automatically, leaving only the target material
Example: With lambert→openPBRSurface.mmap and openPBRSurface→VRayMtl.mmap but no lambert→VRayMtl.mmap, the tool automatically completes lambert→openPBR→VRayMtl.

5. Handling Failed Conversions

A single failed material never interrupts the batch conversion:

  • Materials with no mapping file or with conversion errors are skipped and conversion continues
  • After conversion, a dialog lists the failed materials and the reasons
  • The dialog provides a "Select Failed Materials" button to select all failed materials in the Maya viewport for inspection

If the "No Mapping → Default" option is checked, materials with no mapping file are not reported as failed; instead, a basic target-type material is created to replace the source (type-correct only, no attributes are copied).

6. Preset Management

Preset File Location

Preset files are stored in the tool's preset/ directory with the .mlist extension.

Preset File Structure

Preset files are JSON and contain a list of mappings:

{
  "version": "1.0",
  "mappings": [
    {"source": "lambert", "target": "aiStandardSurface"},
    {"source": "phong", "target": "redshiftStandardMaterial"},
    {"source": "", "target": "aiStandardSurface"}
  ]
}

Preset vs Mapping File

TypeExtensionPurpose
Preset.mlistStores the "source type → target type" correspondences
Mapping file (Map).mmapStores the detailed "source attribute → target attribute" mapping rules
Combined usage: Presets define "what type converts to what type"; mapping files define "how attributes are transferred between types". Both work together for the full conversion workflow.

7. Usage Tips

  1. Test on a small scale first: use "Convert Selection" on one or two materials before "Convert All"
  2. Unify target type: to convert all materials to a single PBR type, use the "empty source + single row" configuration
  3. Leverage openPBR: prepare one "→openPBR" and one "openPBR→" mapping per renderer to cover conversions between any renderers
  4. Reuse mappings: once a material type conversion works, the preset and mapping files can be reused forever
  5. Process in batches: convert complex scenes in stages (e.g. lambert first, then phong)
  6. Check failed materials: after conversion, use the "Select Failed Materials" button to locate and fix them
  7. Team sharing: put the preset/ and mapping folders on a shared path to standardize team conversions

8. FAQ

Q: The converted material looks wrong?

A: In most cases the .mmap mapping file is incomplete. Use the "Material Node Attribute Mapping" tool to create more detailed mapping rules.

Q: No matching .mmap file found?

A: There is no matching mapping file in the mapping folder. You can:
1. Create a matching mapping file (or prepare openPBR intermediate mappings)
2. Use the "Material Node Attribute Mapping" tool to create a new mapping file
3. Or enable the "No Mapping → Default" option to let the tool create a default target material

Q: The conversion failed?

A: Check the following:
1. Whether the target renderer plugin is loaded (Arnold / Redshift)
2. Whether the source node type name is spelled correctly (case-sensitive)
3. Whether there are name conflicts between materials in the scene
4. Use the "Select Failed Materials" button to locate the exact problem materials

Q: The conversion is slow?

A: Batch conversion of large scenes processes nodes one by one, which is normal. Watch the status bar progress. If it hangs, check for complex node networks.

Q: Can the conversion be undone?

A: With the "Keep Original Material" option enabled, source nodes are not deleted, so you can delete the target materials and reuse the sources. For a permanent conversion, save the scene first.

Q: Which renderers are supported?

A: Theoretically all renderers loaded in Maya are supported. Common ones:
• Arnold (aiStandardSurface)
• Redshift (redshiftStandardMaterial)
• V-Ray (VRayMtl)
• RenderMan (PxrSurface)
• Stingray (StingrayStandardMaterial)
Renderers without a direct mapping can still be converted through the openPBR intermediate format.
