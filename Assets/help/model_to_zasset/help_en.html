Model Asset to zasset Tool - User Help

1. Tool Overview

This tool converts various 3D model formats (ma, mb, obj, usd, abc, fbx, etc.) into the unified .zasset asset format, making asset management and quick access easy.

  • Merges multiple files of the same name in different formats into a single asset
  • Automatically collects dependency files (textures, materials, etc.)
  • Reads metadata from existing asset management tools (e.g. Zoo Tools json files)
  • Preserves source filenames without modification
  • Allows custom target formats
  • Recursively searches deep directories for model files
  • Supports including the contents of subfolders such as ass/ and textures/

3. Interface

3.1 Input Settings

Model folder: Select the folder containing the model files. The tool automatically scans them for model files.

3.2 Output Settings

Output location: Choose where the converted zasset files are stored. If not set, they are output to the category folder currently selected in the asset library.

3.3 Conversion Options

  • Target formats: A comma-separated list of formats, e.g. ma,usd,abc. Leave blank to package all discovered formats.
  • Include subfolders: When checked, scans and packages files from subdirectories such as ass/, textures/, and sourceimages/ into the zasset.
  • Recursively search subfolders: When checked, scans deep directories for model files (useful when multiple assets are organized in subfolders).
  • Include dependency files: When checked, automatically collects the textures and material files referenced by .ma files.
  • Use existing metadata and thumbnails: When checked, reads metadata files such as json and existing thumbnails.

3.4 File Routing Configuration

Defines the internal directory structure of model and dependency files inside the zasset. You can add custom routing rules to specify the target folder for each extension.

  • root: model files (ma, mb, obj, usd, abc, fbx, mcm, zmetal, mtl)
  • textures: texture files (jpg, png, exr, tga, hdr, dds, etc.)
  • ass: Arnold proxy files

3.5 Metadata Source Configuration

Configures thumbnail search paths and metadata sources for extracting information from the asset format of existing asset management tools (e.g. Zoo Tools).

  • Thumbnail search path: supports dynamic path patterns with {assetName} variable substitution
  • Metadata source: defines file path templates, formats, and field mapping rules

3.6 Model Preview

The right panel shows the list of scanned model assets and a preview of the subfolder contents. Select an asset to view its included file formats and sizes.

4. Workflow

Step 1: Prepare source files

Place the model files in the same folder. Files with the same name but different formats are treated as a single asset.

Step 2: Select the input folder

Click "Browse... " to select the folder; the tool automatically scans the model files.

Step 3: Configure options

Set options such as target formats, subfolder inclusion, and recursive search.

Step 4: Click "Scan Models"

View the scan results and the preview of subfolder contents.

Step 5: Click "Convert"

The tool automatically collects files, reads metadata, generates thumbnails, and builds the zasset.

5. Asset Naming Rules

The tool uses the filename (without extension) as the asset name and preserves the original filename unchanged.

Source fileAsset name
SciFi_Fighter_BLNN.maSciFi_Fighter_BLNN
subdir/character_v1.macharacter_v1 (displayed as subdir/character_v1 in recursive mode)
Multiple formats with the same name: aaa.ma, aaa.mb, aaa.obj, and aaa.usd are treated as the same asset, and all formats are packaged into the same zasset.

6. Subfolder Content Inclusion

3D assets often store Arnold proxy caches, sequence textures, file dependencies, etc. in subfolders. The tool supports automatically scanning and including these files.

6.1 Default Subfolders

SubfolderContent
ass/Arnold proxy files (.ass cache sequences)
textures/Texture files
sourceimages/Maya standard texture directory

Subfolder contents are packaged into the zasset while preserving their original relative path structure:

pSphere1.zasset/
├── meta.json
├── pSphere1.ma
├── ass/pSphere1_1001.ass    ← keeps the ass/ directory structure
└── textures/dd_diffuse.png  ← keeps the textures/ directory structure

7. Dependency File Collection

The tool collects dependency files through the following methods:

  1. Parse .ma files: read the texture reference paths in Maya ASCII files
  2. Same-directory scan: search for .mtl, .mcm, and .zmetal files with the same name as the asset
  3. Standard path search: search for textures in the textures/ and sourceimages/ directories

Supported texture formats: .jpg, .jpeg, .png, .tga, .tif, .tiff, .exr, .hdr, .bmp, .tx, .dds

The tool automatically creates a texture_map field recording the mapping from the original path to the internal zasset path:

"texture_map": {
    "C:/Projects/textures/my_diffuse.jpg": "textures/my_diffuse.jpg"
}

10. Configuration File

The tool uses the model_mapping.json configuration file, located in the same directory as the tool:

  • category_mapping: automatically infers the category based on keywords in the asset name
  • file_routing: defines the target directory for different file types
  • thumbnail_search_paths: thumbnail search path pattern
  • metadata_sources: metadata source file path templates and field mappings
  • format_priority: format priority order

11. FAQ

Q: Why is my model not recognized?

A: Make sure the file extension is in the supported list (.ma, .mb, .obj, .usd, .usda, .usdc, .abc, .fbx, .ass).

Q: Textures are not being collected correctly?

A: Confirm that the .ma file contains texture reference paths, that the texture files are in the same directory or in textures/, and that "Include dependency files" is checked.

Q: Subfolder contents are not being included?

A: Make sure "Include subfolders" is checked, and that the subfolder names are in the list (default: ass, textures, sourceimages).

Q: How do I convert only specific formats?

A: Enter a comma-separated list of formats in the "Target formats" input box, e.g. ma,usd,abc.

Q: Metadata is not being read?

A: Confirm that the json file exists in the *_Dependencies/ or *_ma_Dependencies/ directory.

12. Dependency Installation

The following Python libraries are required:

  • PIL/Pillow (thumbnail generation)
  • PySide2/PySide6 (UI)

Installation:

# System terminal
pip install Pillow

# Maya environment
"C:\Program Files\Autodesk\Maya2025\bin\mayapy.exe" -m pip install Pillow
